# Studio Console — P2–P6 Implementation Notes

_Companion to `02_BLUEPRINT.md` (P0+P1). Written 2026-11-12, on the
branch that implements P2–P6. Everything below that claims a number
names its source; everything that could not be verified says so._

## What shipped

### P2 · First-party analytics (`/studio/analytics`)

The vendor plan still cannot return event aggregates (HTTP 402), so the
site now stores its own copy of every event:

- `collections/AnalyticsEvents.ts` + migration
  `20261112_100000_analytics_events` (hand-written, like the `ms`
  widening, because `migrate:create` still tries to bundle the
  `projects.status` drift from `03_SCHEMA_FINDINGS.md` §3). The snapshot
  JSON is the previous snapshot plus exactly the new table and the
  locked-documents relation — pinned by
  `lib/payload-schema-audit.test.ts`. Gate result on a migrations-only
  database: `exactSnapshot: true`, `releaseReady: true`.
- `POST /api/track` — the only public write path. The collection's REST
  create stays admin-only, so nothing bypasses the sanitizer or the
  per-IP rate limit (120/min). Bots are refused by user-agent; storage
  failures return the same 204 as successes so analytics can never
  break or slow a visitor action.
- `lib/analytics-events.ts` — the privacy contract as pure functions:
  allowlisted names, local paths only (no query strings), host-only
  referrers, per-key property sanitization (an email-shaped value is
  dropped, the event is kept), coarse device class, no IP / UA /
  fingerprint stored. Session = random `sessionStorage` id.
- `lib/analytics.ts` dual-sends (vendor unchanged) and
  `components/seo/pageview-tracker.tsx` emits one `pageview` per route
  change from the site layout.
- `/studio/analytics` — pageviews, sessions, enquiries saved, events
  stored (each tile states its definition), daily area chart, session
  funnel (distinct sessions per step, explicitly not forced nested,
  with session-id coverage printed), top pages (locale prefixes
  folded), referrer hosts + campaigns, language/device, event mix.
  The Overview gained an aurora "Traffic" tile fed by the same store.

Definitions that matter: a **pageview** is one stored `pageview` event;
a **session** is a distinct random per-tab id, not a person;
**enquiries saved** is counted from `messages`, and when the browser's
`contact_submit` signal and the database disagree, the console says to
believe the database.

Verified live locally: seeded 124 events + 16 leads; rendered tiles
matched SQL ground truth exactly (126 events / 118 pageviews / 115
sessions / 12 enquiries after two curl beacons); a curl-submitted
`email` property was dropped at ingest while the event was stored;
unknown events and bot user-agents got 422; every console route 200
with a session, and unauthenticated requests carry zero lead data.

### P3 · CRM depth (`/studio/leads`)

- The board is now a working board: drag a card between the four open
  stages, or open the drawer. Writes go through
  `app/studio/leads/actions.ts` with the operator's own Payload session
  (`overrideAccess: false`) — Payload's access rules remain the only
  write path. A failed save reverts the card and toasts the reason.
- The drawer shows the full enquiry (brief, attribution, timeline) and
  edits stage / proposal value / won value / closed reason / read flag
  with the same enums as `collections/Messages.ts`. Opening a lead
  marks it read (optimistically, reverted loudly on failure). Lost and
  Not-a-fit stay off the board by design; they are reachable from the
  drawer's stage select.
- Not browser-verified: this sandbox cannot render, so drag-and-drop
  and the drawer were checked by type-check, code path, and the server
  actions' shared `payload.update` pattern — a real-browser pass is
  still owed.

### P4 · Content performance + SEO (`/studio/content`)

- "Most read content": first-party pageviews joined to posts and case
  studies by slug (locale prefixes folded). Honest empty states when
  the collector has no data or no content views.
- "SEO checks": computed from the CMS rows at request time — published
  post without a standfirst (it literally is the meta description),
  over-length titles, duplicate slugs, published projects with no
  thumbnail or with a card that leads nowhere, case studies missing
  their Arabic name, stale drafts. Every issue links to the exact
  Payload document.
- Search Console: **not connected**, and shown as such with the exact
  env vars that would connect it (`GOOGLE_SEARCH_CONSOLE_PROPERTY`,
  `GOOGLE_SERVICE_ACCOUNT_EMAIL`, `GOOGLE_SERVICE_ACCOUNT_KEY`). The
  tile flips to "credentials present" when they exist; the query client
  itself is deliberately not built yet, so no organic numbers are
  implied anywhere.

### P5 · System health (`/studio/system`)

- Probes now include the first-party collector (real counts: events in
  the last 24 h / all-time, with "installed but silent" distinguished
  from "broken"), the migration ledger (every committed migration
  recorded in `payload_migrations`, dev-push marker detected), and the
  enquiry inbox (newest saved enquiry's age).
- An environment matrix lists each integration variable as set/missing
  with what it powers. Presence only — values never leave the server
  (the deployed commit's short SHA is the one non-secret hint shown).
- The "not verified from here" list stays: deployment status and Core
  Web Vitals still cannot be read from inside the app, and say so.

### P6 · Manage (`/studio/manage`)

- Every collection with its real row count (and draft count where
  `_status` exists), grouped Content / Inbox / System, each with Open
  and New doors into Payload; the two globals with last-edited times.
  The sidebar's flat list of raw `/admin` links is gone — the filing
  cabinet lives behind this one screen. Editing still happens only in
  Payload; this screen is the map, not a second editor.

### Design pass (the NPF reference, translated)

Borrowed experience architecture, kept Aboalazm identity (coral on
obsidian glass, Montserrat/JetBrains Mono): bento tiles with an aurora
variant, grouped sidebar by question, drawer + toasts + skeletons
(`app/studio/loading.tsx`), dependency-free SVG charts, and a tuned
light theme (`.studio[data-theme="light"]` — warm paper, white glass,
deepened coral; the dark-by-design invert tiles re-declare the dark
ramp inside themselves). Theme persists in `localStorage`
(`abo-studio-theme`); dark is the pre-JS paint, so a light-theme
operator can see one dark frame on a hard load.

**Not visually verified.** This sandbox has no browser. The CSS is
token-scoped and test-guarded, but nobody has looked at these screens.
A real-browser screenshot pass — both themes, board drag, drawer — is
required before calling the design accepted.

## Release note

Merging this branch makes the production build's schema gate fail
until the production Neon database has run the new migration — the
gate working as designed, exactly as with PR #87:

```
DATABASE_URI=<production Neon URI> PAYLOAD_SECRET=<production secret> npx payload migrate
```

Then redeploy and confirm `releaseReady: true` in the build log.
