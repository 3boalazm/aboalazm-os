**Date:** 2026-10-09  
**Base:** `main` @ `cfaeb07` (after PRs #13, #14, #24, #25)  
**Scope:** the whole site and repository: browser crawl of every route, site inventory, asset inventory, re-verification of all 107 findings of `QA_REPORT_2026-10-04.md` against the current code, and fixes for everything a developer can fix without owner input.

## 1. Method and limits
- Production build of `main` served locally, every page loaded in Chromium at 375 / 768 / 1440 px (dark) and 1440 px (light) with axe-core 4.10.2 on both desktop views: 30 routes × 4 views = 120 loads, 0 navigation errors, 1,208 images checked.
- Each of the 107 QA findings was re-checked against current source/build by one agent and, when it was still open, independently re-checked by a second agent whose instruction was to refute it. 66 survived that.
- Fixes were written in isolated git worktrees, reviewed adversarially, revised, and integrated here. After integration: `npm run typecheck` clean, `npm run build` succeeds, and a lean re-crawl (section 5) was run on the integrated build.
- **Not checkable from the sandbox:** the live `*.vercel.app` deployment and Neon (blocked), so DB-driven content (Payload posts, CMS case-study rows), live response headers, Vercel Analytics, external link liveness and real screen-reader output are unverified. Findings that depend on them are marked *not checkable*, never guessed.
- Not covered by the crawl: Arabic/RTL pass of every page (done only for the changed components), keyboard/focus order of every page, performance timings on real devices.
