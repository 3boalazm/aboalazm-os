Site: https://aboalazm-os.vercel.app (main). Method: 10 parallel dimension auditors (links, SEO, performance, security, content, i18n source, responsive, accessibility, interactions, Arabic/light rendered), each finding re-checked by an independent adversarial verifier on the live site. GET-only; no forms submitted, no login attempts.

Note: several dimensions independently reported the same issue (e.g. OG 500s, soft 404s, /work-ui Zad 502, mobile menu Escape); duplicates are kept so each dimension's evidence stays intact.

### 1. [high] Per-page OG/Twitter share images return HTTP 500 on all 27 posts, 5 case studies and 3 books, even on the working vercel.app domain

- **Area:** links
- **Pages:** /writing/*, /case-studies/*, /books/basics-of-design, /books/visual-identity, /books/marketing-fundamentals
- **Evidence:** I took the og:image paths from the live HTML and requested them on https://aboalazm-os.vercel.app. Each returned 500 with Content-Length 0 and X-Matched-Path /case-studies/[slug]/opengraph-image-1ieeiq. Examples: GET /writing/the-split-brand/opengraph-image-cvh5yn?c2b6a04400c766b8 -> 500; /writing/the-split-brand-ar/... -> 500; /writing/arabic-deserves-design/opengraph-image-cvh5yn -> 500; /case-studies/code-canvas/opengraph-image-1ieeiq?3b0d82ab0afda0e5 -> 500; /books/visual-identity/opengraph-image-6941mx?2faf7fa9a2b81207 -> 500. The root card works: GET /opengraph-image-12o0cb?0addb2778320b032 -> 200 image/png, 238975 bytes. This is a separate bug from known issue #2 (the aboalazm.com host). After PR #10 fixes the domain, every post, case-study and book share preview will still be broken. The books route makes no DB call (getBook is a static list) and still fails, so the database is not the cause.
- **Root cause:** lib/og.tsx:33. ogFonts() reads fonts at request time with readFile(path.join(process.cwd(), "public/fonts", file)). The root app/(site)/opengraph-image.tsx is prerendered at build, so it works. The [slug] image routes render at runtime in the Vercel function, and nothing in next.config.ts sets outputFileTracingIncludes. So public/fonts/Gc_Epicpro.otf and thmanyahserifdisplay-Bold.otf are probably not bundled into the function, and readFile fails. This is inferred: the only code shared by all three failing routes is ogFonts(), and the static one works. I could not see Vercel function logs.
- **Fix:** Add outputFileTracingIncludes to next.config.ts, for example { '/writing/[slug]/opengraph-image*': ['./public/fonts/Gc_Epicpro.otf','./public/fonts/thmanyahserifdisplay-Bold.otf'], plus the same for case-studies and books }. Alternatively, load the fonts with fetch(new URL('../public/fonts/Gc_Epicpro.otf', import.meta.url)).then(r=>r.arrayBuffer()) so the bundler includes them. You can also export generateStaticParams from each [slug]/opengraph-image.tsx so the cards are prerendered at build. Then check with curl -I that each og:image URL returns 200 image/png.
- **Verifier:** Reproduced on 2026-10-04. The og:image meta on /writing/the-split-brand, /case-studies/code-canvas and /books/visual-identity points at aboalazm.com, which is known issue #2. Requesting the same paths on aboalazm-os.vercel.app gives HTTP 500, Content-Length 0, X-Vercel-Cache MISS. X-Matched-Path is /writing/[slug]/opengraph-image-cvh5yn, /case-studies/[slug]/opengraph-image-1ieeiq and /books/[slug]/opengraph-image-6941mx. The root /opengraph-image-12o0cb returns 200 image/png, 238975 bytes, cache HIT. Source check: lib/og.tsx:31-33 reads fonts with readFile(path.join(process.cwd(),'public/fonts',file)), and next.config.ts has no outputFileTracingIncludes. app/(site)/books/[slug]/opengraph-image.tsx:14 calls ogFonts(). The missing-font root cause is a strong inference only, because Vercel logs were not visible. The status is independent of the host, so this stays broken after PR #10 fixes the domain. High is appropriate.

- **Area:** seo
- **Pages:** /writing/* (27 posts), /case-studies/{ahmed-bedeer,code-canvas,gad-institute,nile-pharma,reflection}, /books/{basics-of-design,visual-identity,marketing-fundamentals}

All 35 dynamic endpoints (writing /opengraph-image-cvh5yn, case-studies /opengraph-image-1ieeiq, books /opengraph-image-6941mx) give 500 with an empty body. Only the static root image works: /opengraph-image-12o0cb returns 200 image/png, 238975 bytes, 1200x630. The book endpoints also fail, and getBook() is a synchronous in-repo lookup that never touches the DB, so the DB is not the cause. The shared font loader is the common factor. The font files are served from the CDN (GET /fonts/Gc_Epicpro.otf returns 200 font/otf, 24644 B). The root app/(site)/opengraph-image.tsx is prerendered at build time, when public/ exists, which is why it alone works. I inferred this from the code and response pattern; I did not see the Vercel function logs.
- **Fix:** Bundle the fonts with the function. Either add `outputFileTracingIncludes: { '/**/opengraph-image*': ['./public/fonts/Gc_Epicpro.otf', './public/fonts/thmanyahserifdisplay-Bold.otf'] }` to next.config.ts, or load them with `fetch(new URL('../public/fonts/Gc_Epicpro.otf', import.meta.url)).then(r => r.arrayBuffer())` (or move the fonts next to lib/og.tsx and read them via import.meta.url). Alternatively, prerender with generateStaticParams in each opengraph-image.tsx. Then check that 1-2 URLs per type return 200 image/png at 1200x630.
- **Verifier:** Confirmed on the live site. These GETs return 500 with an empty body: https://aboalazm-os.vercel.app/writing/the-split-brand/opengraph-image-cvh5yn?c2b6a04400c766b8, /case-studies/nile-pharma/opengraph-image-1ieeiq?3b0d82ab0afda0e5, /books/basics-of-design/opengraph-image-6941mx?2faf7fa9a2b81207 and /books/visual-identity/opengraph-image-6941mx. ### 3. [high] LCP text is hidden in the server HTML and only appears after hydration and animation delays (mobile lab LCP 3.8-4.4s on home, 6.0-7.5s on posts)

- **Area:** perf
- **Pages:** /, /writing/the-split-brand, /writing/*, /work, /gallery, every page (nav)
- **Evidence:** The server HTML (curl, cache HIT) ships the above-the-fold content invisible. On home, each H1 line is wrapped in `<span class="block will-change-transform" style="transform:translateY(110%) rotate(1.5deg)">` inside an overflow-hidden span, so it is clipped out of view. The lead <p> has `style="opacity:0;filter:blur(6px);transform:translateY(28px)"`. The <nav> has `style="opacity:0;transform:translateY(-12px)"` on every page. Counts of opacity:0 in the SSR HTML: / 14, /work 7, /gallery 53, /writing/the-split-brand 70 (every word of the H1 is a separate opacity:0 span). Lab method: local headless Chrome 154, Moto G Power profile (412x823, DPR 1.75), 150ms RTT, 1.6Mbps, 4x CPU, cold cache. Results: / FCP 1.14-1.54s, LCP 3.82s / 4.03s / 4.35s over 3 runs, LCP element = `P.max-w-[46ch] text-lead` (the hidden lead). /writing/the-split-brand FCP 1.16s, LCP 7.46s, LCP element = the last H1 word span `personalities`. /writing/the-split-brand-ar LCP 6.01s. Desktop home (no CPU throttle): FCP 356ms, LCP 916ms. The 2-4s gap between FCP and LCP on mobile is the time to download and hydrate about 280KB of JS, plus framer delays (heroLine delay 0.1+i*0.12 with the 'cinematic' transition; post words delay 0.08+i*0.05; nav delay 0.9s). With JS disabled or failing, the hero headline, lead and nav never become visible.
- **Root cause:** features/hero/hero.tsx:107-131 (motion.span with variants=heroLine and initial="hidden"; motion.div with reveal.container/item). lib/motion.ts:67-87 (reveal.item.hidden = {opacity:0, y:28, filter:'blur(6px)'}; heroLine.hidden = {y:'110%'}). app/(site)/writing/writing-detail-view.tsx:189-236 (per-word motion.span initial={{opacity:0,y:28}}; standfirst delay 0.35; it also ignores prefers-reduced-motion, unlike hero.tsx). components/layout/nav.tsx:68-72 (nav initial opacity 0, delay 0.9).
- **Fix:** Never gate the LCP element or the nav on JS. Options: (1) set initial={false} on the H1 lines, the lead paragraph and the post title/standfirst, so they render visible in SSR, and keep the animations for secondary elements below them; or (2) move the hero entrance to a pure CSS @keyframes animation (transform only, with no opacity/blur on the LCP node) that starts at first paint, not at hydration. Drop the nav's 0.9s delay and SSR opacity:0. Route the writing-detail animations through useEntrance()/useReducedMotion like hero.tsx does.
- **Verifier:** Confirmed. The curled live SSR HTML matches the report. On /, the H1 lines carry style=transform:translateY(110%) rotate(1.5deg) and the lead is <p class="max-w-[46ch] text-lead ..." style="opacity:0;filter:blur(6px);transform:translateY(28px)">. Every page has <nav aria-label="Primary" style="opacity:0;transform:translateY(-12px)">. opacity:0 counts match exactly: / 14, /work 7, /gallery 53, /writing/the-split-brand 70. Source matches features/hero/hero.tsx:107-131, lib/motion.ts:67-87, components/layout/nav.tsx:68-72 (delay 0.9) and app/(site)/writing/writing-detail-view.tsx (per-word initial opacity 0, delay 0.08+i*0.05, standfirst delay 0.35, no useReducedMotion). My own CDP lab run used Chrome 154 with the Moto G profile, 150ms RTT, 1.6Mbps and 4x CPU. Home: LCP element was the same hidden lead P, LCP 4604/9548ms against FCP 2056/3500ms. /writing/the-split-brand: LCP element was the last H1 word span 'personalities', LCP 9900/9736ms against FCP 4540/3576ms; the LCP candidates step through the word spans from about 9.2s to 9.9s. My absolute times are higher than the original's because the local network was flaky (intermittent DNS failures), but the pattern is the same: FCP comes early and LCP waits on hydration and the animations. On posts this puts LCP well over the 4s 'poor' threshold, so I kept it at high.
